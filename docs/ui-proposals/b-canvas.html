UI overhaul · Proposal B

Canvas-first: floating controls and a command palette

Keep the original's spirit, a full-bleed drawing surface driven by the keyboard, but make it discoverable. The menu bar and HUD bars go; small floating pieces appear only where they help, and a searchable command palette (Ctrl+K) lists every action with its shortcut.

    Live mock: press Ctrl+K (or click “Search commands”) and type, Esc closes. Dock toggles redraw the scene; the palette chip cycles palettes.

    What changes

    Added

    • Command palette: every action from the F1 list and the menus, fuzzy-searchable, shortcut shown.
    • VP chip strip: 9 slots, placed / empty / selected at a glance.
    • Selection popover next to the selected point (density, level).
    • Context toast replaces the red prompt text in the top bar.

    Removed / moved

    • Window menu bar (on macOS the native menu keeps it).
    • Both HUD bars; zoom and FOV move to a small meta chip.
    • F1 overlay becomes the command palette pre-filtered to shortcuts.

    Build cost

    • Overlay panel above ViewportControl in a single-cell Grid.
    • One command table (name, gesture, action) feeding palette, menus and help: removes the duplicated lists in Renderer.DrawHelp and MainWindow.axaml.
    • Low–medium effort; largest share is the palette's filtering and focus handling.

    Risks

    • Floating chrome can cover the plane; dock and chips need auto-fade while dragging.
    • Less obvious to mouse-only users than Proposal A.
